## 统一异常与日志验证

使用 Django 测试客户端注入未预期异常：

```sh
cd backend
./.venv/bin/python manage.py shell -c '
import json
from unittest.mock import patch
from django.test import Client, override_settings
from users.serializers import RegisterSerializer

leak = "password=super-secret-value token=eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjM0In0.c2lnbmF0dXJlMTIzNDU2"
with override_settings(ALLOWED_HOSTS=["testserver"]):
    with patch.object(RegisterSerializer, "create", side_effect=RuntimeError(leak)):
        response = Client().post(
            "/api/auth/register",

print("STATUS", response.status_code)
print("BODY", response.content.decode())
```

- 响应状态 `500`，响应体为 `{"code":"internal_error","message":"服务器内部错误，请稍后重试"}`。
- 日志中未出现原始密码、JWT、Authorization 请求头、密码哈希或数据库密码；响应未包含堆栈。
- 预期 4xx（重复账号、密码错误、缺少/无效 Token）未产生异常堆栈日志。

## OpenAPI 契约同步

实际实现与 `openapi.json` 的路由、成功响应结构和错误结构一致。本轮同步了以下字段约束与说明：

- `RegisterRequest.username` 增加 `maxLength: 150` 和字符说明。
- `RegisterRequest.password` 由 `minLength: 1` 调整为 `minLength: 8`，补充至少两类字符与 Django 密码校验说明。
- `RegisterRequest.display_name` 增加 `maxLength: 150`，说明字段为昵称。
- `LoginRequest.username` 增加 `maxLength: 150`，补充凭据错误统一提示说明。
- `User.username`、`User.display_name` 增加 `maxLength: 150`。
- 顶层 `info.description` 标注已实现接口与后续设计草案。
- 新增 `users.0002`，仅将 `display_name` 的模型显示名改为“昵称”，字段名保持不变。
- 申请列表 `keyword` 参数补充 `maxLength: 100`，`scope` 说明 pending 本轮返回 400。
- `Error.code` 补充 `validation_error`、`invalid_credentials`、`unauthorized`、`scope_not_available`、`conflict`、`forbidden`、`not_found`、`internal_error` 等实际错误码。
- 顶层描述更新为已实现 9 个操作：3 个认证接口、用户列表及 5 个草稿接口。
